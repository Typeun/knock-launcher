# 技术笔记：怎么把「指关节敲击」认出来

## 1. 先排除掉「接触面积」

直觉上最容易的做法是读接触面积（`ABS_MT_TOUCH_MAJOR`）——指关节面积远大于指尖。

**实测结论：不行。**

```
$ adb shell getevent -pl /dev/input/event7
  name: "focaltech_ts"
  ABS_MT_TOUCH_MAJOR : min 0, max 255     <-- 能力表里有
  ABS_MT_WIDTH_MAJOR : min 0, max 119998  <-- 能力表里有
```

但实际抓 20 次触控，**这两类事件一条都没发过**（只有坐标 / TRACKING_ID / SLOT）。
—— 驱动声明了能力，固件并不上报。

同理，**没有 `ABS_MT_PRESSURE`**。

## 2. 退而求其次：三路互证

| 信号 | 采样方式 |
|---|---|
| 加速度计 | `SensorManager`，`SENSOR_DELAY_GAME`，取 `\|a\|-g\| ` |
| 麦克风 | `AudioRecord` 48kHz 单声道，1ms 一跳的 RMS 包络 |
| 触摸事件流 | root 读 `/dev/input/event*`，统计单次触控内的事件条数 |

判定：**加速度峰值 > 阈值 且 ±260ms 内有麦克风瞬态 且 有「事件数够多」的一次触控**。

## 3. 实测分布（一次标定，各 10 次）

| 信号 | 指关节敲 | 指尖点 |
|---|---|---|
| 加速度峰值 | 6.0 ~ 21.9 m/s² | 1.8 ~ 5.7 m/s² |
| 麦克风包络瞬态 | 620 ~ 903 | 150 ~ 413 |
| 单次触控事件数 | 中位 **52** | 中位 **3** |

严格「三路同时命中」：指关节 **6/10 命中**，指尖 **0 误报**。

**触控「时长」不是判据**（74ms vs 78ms，基本一样）—— 这条一开始猜错了。

## 4. 但个体差异很大

同一个人，「平时力度敲」和「很用力敲」差得很远；
「很用力用手指按」也能越过幅度阈值 → 误触。

所以光靠固定阈值不够稳，理想做法是**用本人的样本自动标定**（`RecorderActivity` 就是干这个的）。

## 5. 已知坑

- **同一时刻只有一个采集方能拿到麦克风**（Android 10+）。
  所以录制标定样本前，必须先停掉常驻服务，否则录到的全是静音。
- 后台启动的 Activity **不能弹出输入法**。选择器要能用搜索，得自动聚焦 + 强弹，或改走全屏通知/悬浮窗。
- `screencap` 用 root 跑，写出来的文件属主是 root，记得 `chmod`。
